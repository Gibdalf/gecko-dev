## Diagnosis
Mozilla is rolling out eslint. As part of this change, linting rules need to be applied to the dom/promise directory.

## Solution
The following instructions were provided by Mark Banner (the bug's creator):

1. in .eslintignore, remove the dom/promise/** line
2. run eslint `./mach eslint --fix dom/promise`
3. inspect the diff to make sure that the indentation of the lines surrounding the changes look ok
4. create a commit for the work so far (exclude the changes to .eslintignore for now)
5. for the remaining issues, fix them by hand. To find them, run `./mach eslint dom/promise`
6. create a second commit for the manual changes and .eslintignore
7. when the bug is complete, post the two commits via phabricator

Mark also provided links with information for dealing with no-undef errors. In fixing this bug, no-undefs happened mostly because global variables / functions were declared in inline script tags (for testing), then other scripts which were included in the tests assumed the existence of these globals. I fixed the linter errors by adding an eslint directive to the top of each file where this occurred, listing the globals used in that file.

Another error I had to fix multiple times, was the original authors of the tests sometimes called undeclared functions as a way of thowing an error. I instead explicitly threw ReferenceError to trigger the same behaviour from the tests.
 
## Testing
There are 3 ways I will know if my patch is correct:

1. running the linter will reveal there are now linting errors in dom/promise
2. running tests `./mach test dom/promise` will reveal all the tests still pass
3. Mark will manually review my patch, to make sure he agrees with all the fixes I made
